lean-sdlc is a Claude Code plugin that sizes every task, stops for your approval before features, writes the failing test first and hands the diff to a fresh reviewer.

/plugin marketplace add SubaashNair/lean-sdlc
/plugin install lean-sdlc@lean-sdlc

Then run /lean-sdlc:lean-init once per repo and ask for work as usual.

Sizes every task

S0 One-sentence change

Do it, then run the existing tests. No artifact.

S1 Small change or bug

Failing test first, minimal fix, evidence before "done".

S2 Feature

Write plan.md, stop for approval, build in small slices, review.

S3 Large or ambiguous

Plan with open questions, and ask before building anything.

What you get

lean

The workflow skill. Triggers on features, fixes and refactors; stays out of the way for typos and questions.

lean-reviewer

A subagent that reviews the diff in a fresh context: correctness, stated requirements, scope and simplicity.

lean-init

One-time setup. Picks the solo or team preset and writes .lean/config.yaml, with an optional plan-gate hook.

Two rules hold at every size: a request that contradicts a recorded decision goes back to you, and trust boundaries (input size, parse errors, ownership checks) are always in scope.
